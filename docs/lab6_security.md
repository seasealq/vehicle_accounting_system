# Практическая работа №6: безопасная работа с БД и файлами

## Состояние и границы

ЛР6 продолжает фактическую версию v0.5 и сохраняет API `validate_request(bytes) -> ValidatedRequest`. Демонстрация связывает эту модель с `RequestService`, SQLite и файловым хранилищем. Компоненты реализованы как локальный учебный прототип; в проекте нет сетевого сервера, аутентификации и авторизации заявок.

## Матрица требований, мер и проверок

| Угроза/ошибка | Мера в коде | Проверка | Результат |
|---|---|---|---|
| SQL Injection (CWE-89) | Значения SQL передаются параметрами `?`; динамический `ORDER BY` выбирается из `SORT` | SQL-подобный заголовок остаётся значением; неизвестная сортировка отклоняется | Проверено автотестами |
| Нарушение целостности строки | Ограничения SQLite `NOT NULL`, `CHECK`, `UNIQUE`; строгие типы и диапазоны в API | Категория, приоритет, ID, LIMIT, согласованность типа и ID вложения | Проверено автотестами |
| Path Traversal (CWE-22) | Физическое имя строится только из 32 шестнадцатеричных символов; путь пользователя не принимается | `../secret`, абсолютные и неверные идентификаторы | Проверено автотестами |
| Symlink и TOCTOU (CWE-367) | Открытие корня и файлов через `O_NOFOLLOW`; операции относительно открытого `dir_fd`; `O_EXCL` при создании; `fstat` после открытия | Чтение ссылки на внешний файл; создание поверх ссылки; подмена корня ссылкой | Проверено тремя сценариями на ОС с нужными флагами |
| Неподходящий/избыточный файл | Allowlist типов, максимум 1 МиБ, UTF-8 для log, сигнатуры PDF/PNG | Пустой/большой файл, неправильный тип, неправильная сигнатура | Проверено автотестами |
| Потеря согласованности SQLite и файлов | `RequestService` удаляет файл при ошибке добавления строки | Инъекция ошибки БД и проверка пустого каталога | Проверено; это компенсация, не общая атомарная транзакция |
| OS Command Injection (CWE-78) и внедрение аргумента | В учебном примере executable и параметры фиксированы, `shell=False`, отдельные элементы argv, ограничение длины/типа и таймаут | Строка `example; echo TEST` возвращается как одно значение | Проверено; приложение не нуждается в ОС-командах для CRUD/файлов |

## Требования ЛР6

- **SEC-19:** все значения SQLite передаются отдельно от SQL-текста; структурные SQL-выборы доступны только из allowlist.
- **SEC-20:** вложения хранятся под случайными внутренними ID; размер ограничен 1 МиБ; недопустимые ID, типы и сигнатуры отклоняются.
- **SEC-21:** при ошибке сохранения строки БД после записи файла выполняется компенсирующая попытка удаления файла.
- **SEC-22:** внешние аргументы передаются без оболочки через список аргументов; executable фиксирован, значения проверяются до вызова. Тест подтверждает, что метасимволы остаются данными.

Критерии SEC-19–SEC-22 реализованы и проверены тестами `tests/test_v06.py`; это не подтверждает защищённость полного приложения или развертывания.

Вариант 19 с символьными ссылками относится к SEC-20 и проверяется в AT-22.

Проверены три разные ситуации: чтение ID, путь которого является ссылкой на файл вне хранилища; попытка создать файл поверх заранее созданной ссылки при совпадении случайного ID (цель не перезаписывается, генерация повторяется); замена корневого каталога ссылкой после инициализации хранилища. В третьем случае файловая операция завершается отказом. Тесты условно запускаются только при доступных `symlink` и `O_NOFOLLOW`.

На POSIX/macOS `O_NOFOLLOW` запрещает следование по последнему компоненту при открытии, а `dir_fd` привязывает операцию к уже открытому каталогу. Сам корневой каталог и его родитель должны принадлежать доверенному субъекту; защита не покрывает скомпрометированный процесс, root/администратора ОС или недоверенный родительский каталог. На ОС без `O_NOFOLLOW`, `O_DIRECTORY` или `dir_fd` операция отказывает закрытым образом.

## Ограничения файловой политики

`log` проверяется на строгий UTF-8 и отсутствие NUL; `report` — на `%PDF-`; `screenshot` и `vehicle_photo` — на 8-байтовую PNG-сигнатуру. Это проверка начальных признаков, а не полноценный разбор формата, проверка содержимого, антивирусная проверка или гарантия безопасного отображения. JPEG для `vehicle_photo` не поддерживается. Чтение ограничено `MAX_BYTES + 1` и выполняется по дескриптору, проверенному через `fstat`.

## Тестовые сценарии

`tests/test_v06.py` содержит 28 отдельных тестов. Это превышает 15 базовых ситуаций методички и включает три проверки symlink, положительную/отрицательную регрессию `vehicle_photo`, сквозную интеграцию и передачу аргумента. Полный набор проекта проверяется командой `python -m pytest -q`; точный результат фиксируется после финального запуска.

## Анализ команд ОС

В приложении системная команда не нужна: SQLite и файловые операции выполняются библиотеками Python. Отдельный `safe_argument` приведён только для исследования. `shell=False` означает, что оболочка не разбирает `;`, `&` и другие метасимволы; они остаются байтами одного аргумента. Однако вызываемая программа может интерпретировать аргумент как опцию/путь/режим, поэтому нужны фиксированная программа, allowlist/валидация параметров, лимиты и принцип наименьших привилегий.

## Контрольные вопросы

1. **Что такое SQL-инъекция?** Изменение логики SQL-запроса через внешние данные, попавшие в синтаксис запроса.
2. **Почему она возникает?** Когда данные и текст SQL объединяются до передачи СУБД, например конкатенацией.
3. **Что такое параметризованный запрос?** Запрос с маркерами значений, которые драйвер передает отдельно от SQL-текста.
4. **Почему нельзя включать внешние значения в SQL через f-строки?** Значение может стать частью SQL-синтаксиса; проверка или кавычки не заменяют связывание параметров.
5. **Что такое Allowlist?** Явный конечный набор разрешенных значений или режимов.
6. **Для чего Repository Layer?** Он отделяет операции хранения от бизнес-логики и централизует правила доступа к данным.
7. **Что означает CRUD?** Create, Read, Update, Delete — создание, чтение, изменение и удаление записей.
8. **Что такое Path Traversal?** Обращение к объекту файловой системы за пределами разрешённого каталога через управляемый путь.
9. **Чем абсолютный путь отличается от относительного?** Абсолютный задаёт путь от корня файловой системы; относительный трактуется от выбранного текущего/базового каталога.
10. **Что такое TOCTOU?** Гонка между проверкой ресурса и его последующим использованием, когда ресурс успевает измениться.
11. **Для чего `O_EXCL`?** В сочетании с `O_CREAT` он требует, чтобы имя ещё не существовало, и предотвращает перезапись при создании.
12. **Для чего `O_NOFOLLOW`?** Запрещает открытию следовать по конечному компоненту пути, если тот является символьной ссылкой (на поддерживающих ОС).
13. **Почему пользователь не должен задавать физическое имя файла?** Имя может содержать traversal-сегменты, коллизии или ссылочные конструкции; внутренний случайный ID снижает этот контроль.
14. **Почему ограничивают размер файла?** Чтобы ограничить расход диска и памяти и стоимость последующей обработки.
15. **Почему сигнатура не гарантирует безопасность файла?** Она проверяет лишь ограниченный признак начала; структура, активное содержимое и ошибки декодера остаются за пределами проверки.
16. **Что такое OS Command Injection?** Попадание внешних данных в команду так, что интерпретатор меняет состав или смысл выполняемых команд.
17. **Почему опасен `shell=True`?** Строка передаётся оболочке и может быть разобрана как операторы и команды.
18. **Чем внедрение аргумента отличается от инъекции команд?** При внедрении аргумента запускается заданная программа, но ввод влияет на её опции/операнды; при командной инъекции меняется команда/интерпретация оболочки. Риски могут пересекаться.
19. **Что такое компенсирующая операция?** Отдельное обратное действие, которое пытается отменить уже выполненный шаг после сбоя другого хранилища.
20. **Почему компенсация не даёт полной атомарности?** Между файловой системой и SQLite нет общей транзакции; процесс может завершиться или компенсация сама может не выполниться.
21. **Для чего негативное тестирование?** Чтобы подтвердить контролируемый отказ на ошибочных, пограничных и специально сформированных данных.
22. **Почему успешные тесты не означают абсолютную защищённость?** Они проверяют только конкретный код, окружение и набор сценариев; неизвестные ошибки, платформенные различия и угрозы развертывания остаются.
