# Сценарии приемки

Сценарии задают проверки будущих функций. Все имеют статус **Запланировано, не выполнено**, поскольку соответствующие функции пока отсутствуют. Данные примеров искусственные.

## AT-1 — Анонимный запрос карточки автомобиля (негативный)

- Связанные требования: SEC-1.
- Исходные условия: система доступна; пользователь не вошел; имеется тестовая карточка `ТС-001`.
- Тестовые данные: запрос карточки `ТС-001` без учетных данных.
- Действия: 1) открыть защищенный адрес карточки; 2) зафиксировать ответ; 3) проверить запись ТС.
- Ожидаемый ответ: отказ в доступе или перенаправление на вход без выдачи полей карточки.
- Ожидаемое состояние данных: карточка не изменена, новая поездка/назначение не создана.
- Статус: Запланировано, не выполнено.

## AT-2 — Водитель пытается изменить карточку ТС (негативный)

- Связанные требования: SEC-2, SEC-4.
- Исходные условия: водитель `DRV-001` вошел; карточка `ТС-001` существует.
- Тестовые данные: попытка заменить статус на «Списан».
- Действия: 1) отправить изменение карточки от имени водителя; 2) прочитать ответ; 3) повторно запросить карточку от уполномоченного диспетчера.
- Ожидаемый ответ: отказ в изменении.
- Ожидаемое состояние данных: статус остался прежним; несанкционированное изменение не сохранено.
- Статус: Запланировано, не выполнено.

## AT-3 — Водитель запрашивает чужую поездку (негативный)

- Связанные требования: SEC-2, SEC-3.
- Исходные условия: `DRV-001` вошел; поездка `TRIP-002` принадлежит `DRV-002`.
- Тестовые данные: идентификатор `TRIP-002`.
- Действия: 1) запросить `TRIP-002`; 2) проверить ответ; 3) проверить, что содержимое поездки не раскрыто.
- Ожидаемый ответ: отказ без выдачи маршрута и пробега.
- Ожидаемое состояние данных: поездка не изменена, попытка отказа может быть отражена аудитом после реализации SEC-7.
- Статус: Запланировано, не выполнено.

## AT-4 — Диспетчер меняет карточку ТС (позитивный)

- Связанные требования: SEC-2, SEC-4, SEC-7.
- Исходные условия: диспетчер `DSP-001` вошел; карточка `ТС-001` существует.
- Тестовые данные: новый статус «На обслуживании».
- Действия: 1) открыть карточку; 2) изменить статус; 3) сохранить; 4) повторно прочитать карточку.
- Ожидаемый ответ: подтверждение сохранения.
- Ожидаемое состояние данных: новый статус сохранен; создается запись аудита с субъектом и действием.
- Статус: Запланировано, не выполнено.

## AT-5 — Водитель передает корректный отчет о поездке (позитивный)

- Связанные требования: SEC-2, SEC-3, SEC-6, SEC-7.
- Исходные условия: `DRV-001` вошел; `ТС-001` закреплен за ним; имеется назначенная поездка.
- Тестовые данные: пробег 125 км, дата и маршрут в допустимом формате.
- Действия: 1) открыть свою назначенную поездку; 2) внести пробег и результат; 3) отправить отчет; 4) повторно открыть поездку.
- Ожидаемый ответ: подтверждение приема отчета.
- Ожидаемое состояние данных: отчет связан с назначенной поездкой и сохранен без изменения чужих записей; создается аудит.
- Статус: Запланировано, не выполнено.

## AT-6 — Администратор просматривает аудит (позитивный)

- Связанные требования: SEC-2, SEC-7, SEC-8.
- Исходные условия: администратор `ADM-001` вошел; аудит содержит тестовую запись о смене статуса.
- Тестовые данные: фильтр по `ТС-001`.
- Действия: 1) открыть журнал; 2) применить фильтр; 3) сверить субъект, действие и время.
- Ожидаемый ответ: отображается только подходящая запись с необходимыми полями.
- Ожидаемое состояние данных: просмотр не изменяет журнал; секреты и пароли не раскрываются.
- Статус: Запланировано, не выполнено.

## Прослеживаемость

| Требование | Активы | Сценарий | Охват |
|---|---|---|---|
| SEC-1 | AS-1, AS-2 | AT-1 | Анонимный доступ |
| SEC-2 | AS-2, AS-4–AS-8 | AT-2–AT-6 | Проверки полномочий |
| SEC-3 | AS-2, AS-4, AS-5 | AT-3, AT-5 | Изоляция данных водителя |
| SEC-4 | AS-4 | AT-2, AT-4 | Изменение карточки |
| SEC-5 | AS-2, AS-5 | Матрица доступа, отдельный сценарий не детализирован | Назначения поездок |
| SEC-6 | AS-5 | AT-5 (позитивный); негативная проверка требует отдельного теста | Валидация ввода |
| SEC-7 | AS-7 | AT-4–AT-6 | Запись и просмотр аудита |
| SEC-8 | AS-2, AS-7 | AT-6 (позитивный); запрет водителю покрывает AT-3 только косвенно | Ограничение аудита |
| SEC-9 | AS-1, AS-3 | Отдельный тест | Отсутствие секрета в ошибке |
| SEC-10 | AS-3 | Существующие тесты конфигурации отсутствуют | Проверка конфигурации |
| SEC-11 | AS-1, AS-5 | Проверка развертывания | Защита передачи |
| SEC-12 | AS-9, AS-1–AS-8 | Процессная проверка | Ревью и тестирование |
| SEC-13 | AS-3, AS-9 | Проверка репозитория | Обращение с секретами |

Прослеживаемость показывает требования без подробного сценария; для SEC-5, SEC-9–SEC-13 нужны отдельные проверки при реализации. Шесть сценариев удовлетворяют составу трех положительных и трех отрицательных проверок по предоставленному заданию, но не покрывают все требования.
