# Категории данных и реестр защищаемых активов

Категории данных описывают группы полей; активы — то, ценность чего защищается. Для проектируемого хранилища указано предполагаемое место хранения. Ниже приведены только названия полей и искусственные примеры, реальные персональные данные и секреты не используются.

## Категории обрабатываемых данных

| ID | Категория | Примеры полей | Источник | Предполагаемое хранение | Ограничение доступа |
|---|---|---|---|---|---|
| DT-1 | Профили пользователей | Имя, табельный номер, контакт | Администратор; возможно кадровая система (интеграция не проектируется) | База данных системы, планируется | Сотрудник — собственный профиль; администратор — поля, необходимые для управления учетной записью |
| DT-2 | Учетные данные и роли | Идентификатор входа, хэш пароля, роль | Пользователь и администратор | База данных системы, планируется | Данные проверки не отображаются; роль меняет администратор по установленной процедуре |
| DT-3 | Параметры конфигурации | APP_NAME, APP_ENV, APP_SECRET_KEY | Администратор среды | Окружение процесса или локальный `.env` | Только обслуживающий приложение субъект; секрет не выводится |
| DT-4 | Карточки транспортных средств | Госномер, марка, модель, статус, технические данные | Диспетчер | База данных системы, планируется | Диспетчер — автопарк; водитель — только закрепленные ТС |
| DT-5 | Назначения и поездки | Водитель, ТС, дата, маршрут, пробег | Диспетчер и водитель | База данных системы, планируется | Диспетчер — по рабочим задачам; водитель — только собственные назначенные поездки |
| DT-6 | Техническое состояние и обслуживание | Дефект, работы, дата/срок ТО | Водитель сообщает; диспетчер ведет учет | База данных системы, планируется | Диспетчер изменяет учет; водитель может передать сообщение о дефекте |
| DT-7 | Журналы и отчеты | Субъект, действие, время, результат; сводные показатели | Приложение и диспетчер | Журнал, база данных или экспорт, планируются | Журнал — уполномоченная роль; отчет — по служебной задаче и в минимально необходимом объеме |

## Оценка значимости активов

Используется учебная шкала методички: 1 — низкая значимость (ограниченные последствия); 2 — средняя (нарушается часть работы или требуется заметное восстановление); 3 — высокая (существенное раскрытие, потеря контроля или остановка основных функций). `Ci` — конфиденциальность, `Ii` — целостность, `Ai` — доступность. `Ki = max(Ci, Ii, Ai)` — классификационный показатель значимости, не оценка риска.

| ID | Актив | Ответственный за актив | Ci | Ii | Ai | Ki | Обоснование оценок (Ci / Ii / Ai) |
|---|---|---|---:|---:|---:|---:|---|
| AS-1 | Учетные записи и данные проверки пароля | Администратор безопасности | 3 | 3 | 3 | 3 | Раскрытие может открыть учетные записи; подмена нарушает идентификацию; без входа пользователи не работают. |
| AS-2 | Профили пользователей и роли | Администратор безопасности | 2 | 3 | 2 | 3 | Раскрываются служебные сведения; неверная роль меняет полномочия; восстановление профилей требует ручной работы. |
| AS-3 | Секретный параметр и конфигурация приложения | Администратор среды | 3 | 3 | 2 | 3 | Раскрытие ослабляет защиту; подмена меняет режим работы; конфигурацию можно восстановить из защищенного источника. |
| AS-4 | Реестр транспортных средств | Владелец процесса учета автопарка | 2 | 3 | 3 | 3 | Данные могут раскрыть состав парка; искажение карточек нарушает учет; недоступность останавливает основную функцию. |
| AS-5 | Назначения и сведения о поездках | Владелец процесса диспетчеризации | 3 | 3 | 3 | 3 | Маршруты связаны с сотрудниками; подмена нарушает учет; потеря доступа блокирует диспетчеризацию. |
| AS-6 | Сведения о техническом состоянии и обслуживании | Ответственный за технический учет | 2 | 3 | 3 | 3 | Утечка имеет ограниченный эффект; неверное состояние влияет на эксплуатационные решения; недоступность мешает контролю исправности. |
| AS-7 | Журнал событий безопасности | Ответственный за контроль безопасности | 2 | 3 | 2 | 3 | Может раскрывать действия сотрудников; удаление/подмена мешают разбору событий; краткая недоступность допускает отложенный анализ. |
| AS-8 | Учетные отчеты | Владелец процесса учета автопарка | 2 | 3 | 2 | 3 | Отчет содержит сводные служебные сведения; искажение влияет на решения; отчет можно восстановить из первичных данных. |
| AS-9 | Исходный код и тесты | Разработчик проекта | 1 | 3 | 2 | 3 | Учебный код не содержит закрытых предметных данных; подмена вносит дефекты; исходники восстанавливаются из Git. |
| AS-10 | Работоспособность системы | Владелец сервиса | 1 | 2 | 3 | 3 | Сам факт доступности не раскрывает сведения; краткий сбой не искажает данные; длительная остановка блокирует основные операции. |

Активы AS-1–AS-8 и AS-10 описывают проектируемую систему; AS-9 существует в репозитории. Фактически сейчас реализованы только загрузка конфигурации и проверка длины `APP_SECRET_KEY`; криптографическое применение секрета, база данных и функции учета отсутствуют. Оценки предварительные и не являются результатом анализа угроз/риска лабораторной №3.
